# 法兰报价功能 · 上线计划与多智能体分工

- 目标版本：报价功能 v1.0（可上线）
- 目标站点：现有 Django 标准库站点（`catalog` 只读复用，新增 `quote` 应用）
- 当前日期：2026-11-06
- 目标状态：**不是“能点”，而是“能上线”**：金额可复算、权限可隔离、报价单可打印、数据可追溯、部署可回滚。

## 1. 现状盘点

### 1.1 已经有的

| 资产 | 状态 | 说明 |
|---|---|---|
| Django 4.2 标准库站 | 已有 | `catalog`：1,348 条规格、搜索、规格卡、A4 打印、Playwright PDF |
| 标准数据包 | 已有 | 5 标准/系列、23 个材质主数据、参考数据、字段字典、来源记录 |
| 报价设计 HTML | 已有 | 总览/架构/业务/数据/Excel/工作台/路线 7 个板块 |
| 报价工作台原型 | 已有 | 浏览器端单条报价、成本/定价、p/T、A4 报价单、CSV |
| 重量引擎 w0.3 | 已有（前端） | 标准/几何双来源、B/C 置信度、体积分解、6 项自检 |
| CAD 验证 SOP | 已有 | 4″ 单件 + 10 个规格 10/10 通过；批量脚本、校准脚本、3D 渲染 |
| 部署链路 | 已有 | Nginx + Gunicorn + SQLite/PostgreSQL 配置、备份思路 |

### 1.2 还缺的（上线阻塞项）

- 没有 `quote` Django 应用、模型、迁移、服务层；
- 成本/定价/校验只在浏览器 JS，没有后端可复算引擎；
- 没有价格库（材料价、工艺费率、汇率、生效日期）；
- 没有客户、折扣、报价单编号/版本/状态/审批；
- 没有权限隔离（销售/技术/财务/经理/管理员）；
- 没有后端报价单 PDF、Excel 导出、审计日志；
- 没有单元/集成/E2E/验收测试；
- Excel 导入导出仍是设计，没有落地；
- 重量参考值来自第三方近似表，需在报价单上标来源与口径。

## 2. “可上线”的定义（DoD）

上线前必须全部满足，缺一项不发布。

### 2.1 功能

- [ ] 1,348 条 SKU 全部可选；标准/类型/等级/口径级联正确；
- [ ] 材质、数量、工艺、检测、包装、运费、设计温度/压力可录入；
- [ ] 成本逐项可解释：材料、加工、表面、检测、包装、运费、管理费；
- [ ] 定价：成本加成、客户折扣、数量阶梯、税率、汇率；
- [ ] 报价单：编号、版本、状态、快照、A4/PDF、CSV/Excel；
- [ ] 状态机：草稿→待审批→已批准→已发送→已接受→已转订单；拒绝/过期/作废；
- [ ] 价格库、客户、审批记录、审计日志；
- [ ] 后台可维护价格/客户；标准库保持只读。

### 2.2 正确性

- [ ] `weight/costing/pricing/validation` 单元测试覆盖 ≥90%；
- [ ] 1,348 行全量回归，无 NaN/负值/异常组合；
- [ ] 20 张历史报价回放，金额差异 <0.5%（或逐项解释）；
- [ ] 报价单金额 = 明细 × 数量 + 税，四舍五入一致；
- [ ] 成本快照可回放；价格参数按生效日期取值；历史报价不被新价格改写；
- [ ] 重量 B/C 来源、置信度、重量规则版本进入报价单。

### 2.3 权限与安全

- [ ] 未登录不能访问 `/quote/`、`/quote/prices/`；
- [ ] 销售只看本人报价，经理看全部；成本明细只对技术/财务/经理/管理员；
- [ ] 价格库仅财务/管理员可写；
- [ ] `/admin/` 限制内网/VPN；CSRF、Cookie、密码策略、登录失败限制；
- [ ] 报价版本/审批/价格变更全部留痕；关键表禁止物理删除；
- [ ] 无密钥、无演示价格参数进入生产。

### 2.4 性能与体验

- [ ] 工作台首屏 <1 s；单次计算 <50 ms；
- [ ] PDF 单页生成 <5 s；A4 一页；
- [ ] 手机（390 px）、桌面（1440 px）、打印三种版式正常；
- [ ] 报价单打印/保存 PDF 只输出单据页；
- [ ] 10 个并发用户下 SQLite 不锁死（或按计划切 PostgreSQL）。

### 2.5 部署与运维

- [ ] 迁移脚本可重复执行；新库/旧库都能升级；
- [ ] 环境变量、静态文件、Gunicorn/Nginx 配置齐全；
- [ ] 每日备份 db + PDF；恢复演练通过；
- [ ] 健康检查、日志、错误页、回滚方案；
- [ ] 先 staging，再 production；UAT 签字后发布。

### 2.6 文档

- [ ] 用户操作手册（销售/经理/财务）；
- [ ] 管理员手册（价格库/客户/标准数据）；
- [ ] 部署与回滚文档；
- [ ] 重量/价格数据来源与免责声明；
- [ ] 验收报告（测试项、结果、签字）。

## 4. 技术落地

### 4.1 应用边界

```
catalog（只读主数据）
  Standard / Rating / DimensionRow / ReferenceDoc
        ↑ 外键引用
quote（新增）
  models        报价单/明细/快照/价格/客户/审批
  weight.py     重量引擎（JS w0.3 平移为 Python）
  costing.py    成本
  pricing.py    定价/折扣/税
  validation.py p/T、材质、数量、折扣、价格有效期
  services.py   编号/版本/状态/快照
  prices.py     价格库取值
  pdf.py        A4/PDF（复用 Playwright）
  views.py      工作台/列表/详情/打印
  admin.py      价格/客户/报价单后台
```

### 4.2 关键数据表

- `Quotation`：编号、客户、状态、版本、币种/汇率、有效期、贸易条款、金额、快照、创建人、审批人；
- `QuotationItem`：报价单、DimensionRow、材质、数量、净重、重量来源/置信度、成本 JSON、单价、金额、交期；
- `CostSnapshot`：全部参数、标准版本、价格版本、重量规则、汇率/税率、创建人；
- `MaterialPrice`：牌号、元/kg、生效日期、来源；
- `ProcessRate`：加工/表面/检测/包装/运费、单位、费率、档位、生效日期；
- `Customer`：编码、等级、折扣、币种、账期；
- `ApprovalLog`：报价单、动作、人、意见、时间；
- 复用：`Standard`、`Rating`、`DimensionRow`、`ReferenceDoc`。

### 4.3 页面/接口

- `/quote/` 工作台
- `/quote/list/` 列表
- `/quote/<no>/` 详情/版本
- `/quote/<no>/print/` A4 打印
- `/quote/<no>/pdf/` PDF
- `/quote/prices/` 价格库（权限）
- `/quote/customers/` 客户
- `/quote/dashboard/` 统计（P2）
- JSON：`/quote/options/`、`/quote/calc/`、`/quote/`、`/quote/<no>/status/`

## 5. 多智能体组织

### 5.1 角色

| 角色 | 责任 | 不做什么 |
|---|---|---|
| **Lead / 架构**（我） | 接口契约、脚手架、settings/urls、集成、代码评审、最终验收/发布 | 不长期占用某个功能文件 |
| **backend-core** | models/migrations、weight、costing、pricing、validation、services、核心单测 | 不写页面/模板/admin |
| **pricing-data** | 价格库、客户、工艺费率、admin、导入命令、种子数据、数据测试 | 不改 models/migrations；模型由 backend 先冻结 |
| **web-ui** | views/urls、工作台、列表/详情、A4/PDF、静态资源、移动端、UI 测试 | 不写成本/定价核心 |
| **qa-release** | 独立验收、E2E/浏览器、权限/安全、性能、备份恢复、上线清单 | 不改业务代码；问题交给 owner |
| **excel-bridge**（P3/可选） | Excel 导入/原版式导出 | 不阻塞 v1.0 |

### 5.2 文件所有权（避免冲突）

| 范围 | Owner |
|---|---|
| `stdlib_site/settings.py`、`stdlib_site/urls.py`、`quote/apps.py`、`requirements.txt` | Lead |
| `quote/models.py`、`quote/migrations/*`、`quote/weight.py`、`costing.py`、`pricing.py`、`validation.py`、`services.py`、`tests_core.py` | backend-core |
| `quote/prices.py`、`admin.py`、`management/commands/*`、`fixtures/*`、`tests_data.py` | pricing-data |
| `quote/views.py`、`quote/urls.py`、`templates/quote/*`、`static/css/quote.css`、`static/js/quote.js`、`quote/pdf.py`、`tests_ui.py` | web-ui |
| `tests_acceptance.py`、`scripts/acceptance/*`、`docs/上线验收报告.md` | qa-release |
| `docs/报价功能-接口契约.md`、`docs/上线验收.md`、最终合并 | Lead |

> 迁移文件只能由 backend-core 生成；其他 agent 需要字段变更时，先提给 Lead/backend，不直接改 `models.py`。

### 5.3 依赖与波次

```
Wave 0  Lead：契约 + 脚手架 + settings/urls + 测试库
          │
Wave 1  backend-core：models/migrations → weight/cost/pricing/validation
        pricing-data：模型冻结后 → 价格库/admin/种子
        web-ui：按契约做模板/工作台（mock 数据）
          │
Wave 2  backend-core + pricing-data + web-ui：接口/报价单/状态/PDF/Excel 集成
          │
Wave 3  qa-release：独立验收 + E2E + 权限/安全 + 性能 + 备份/恢复
          │
Wave 4  Lead：staging → UAT → production → 回滚演练
```

- 同时最多 3 个 agent 写代码；
- 每个 agent 一个任务、一个 write scope；完成即报告改动/测试/风险；
- Lead 每天做一次集成门：跑全量测试、检查迁移、合并冲突；
- QA 不参与功能开发，保持独立。

### 5.4 任务板（启动时创建并 claim）

| ID | 任务 | Owner | 依赖 | Write scope |
|---|---|---|---|---|

## 7. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 真实价格参数未定 | 报价不可上线 | 上线前由财务给一版；演示参数禁止进生产 |
| 参考重量来源不统一 | 成本偏差 | 标 B/C 来源；关键件实称；数据来源文档 |
| p/T 只覆盖 3 组 | 选型校验不全 | P1 接入 13 组；缺失显式提示 |
| PDF/Playwright 环境 | 无法出单 | staging 先验；保留浏览器打印兜底 |
| 多 agent 改同一文件 | 冲突 | 文件所有权 + 任务 write scope + Lead 集成门 |
| 范围膨胀 | 延期 | 冻结 P1/P2；Excel/ERP 放 P3 |
| SQLite 并发 | 锁/慢 | 10 并发验收；超限切 PostgreSQL |
