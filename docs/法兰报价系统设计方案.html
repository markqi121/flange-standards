一句话方案

标准库负责「是什么」，报价系统负责「多少钱」。

不重做标准库，也不做 ERP。新增一个 quote 应用，把标准规格当作商品主数据， 用一套可解释的成本引擎和可追溯的报价单，接住销售每天最高频的动作：客户询价 → 出价 → 跟单。

✅ 这一版做

P0–P2
  • 标准法兰选型报价：五套标准、三种类型、全部口径与等级。
  • 成本与定价内核：成本加成 + 客户协议价 + 手工跟价，含审批红线。
  • 报价单闭环：编号、版本、状态、快照、A4 / PDF、CSV 导出。
  • 价格库与客户库：材料价、工艺费率、汇率、客户折扣与付款条件。
  • 移动端可用：展会、客户现场也能选型出价。

⛔ 这一版不做

明确边界
  • 不做标准全文阅读器：不收录标准 PDF、正文与图表。
  • 不做 CAD 出图、工艺排产、工时采集。
  • 不做库存、采购、财务总账——留给 ERP。
  • 不做在线支付与多租户 SaaS。
  • 非标图纸件先手工录入成本，不承诺自动核价。

设计原则

五条约束，决定后面所有取舍

标准库只读

报价系统不复制、不改写标准数据；只加外键与快照，避免主数据被业务污染。

快照可追溯

报价时的材料价、费率、汇率、标准版本固化，半年后还能复算同一张单。

参数版本化

所有价格带 effective_from，按报价日期取价，不覆盖历史。

纯函数可测

成本与定价脱离页面与数据库，输入相同、输出必相同，单测直接覆盖。

先单机后联网

SQLite 单机就能跑；需要多人/多端时再切 PostgreSQL，不提前上复杂度。

技术决策

决策选择理由
前端形态Django SSR + 原生 JS复用现有站点/部署；打印与移动端友好；无构建链。
计算位置服务端纯函数页面 / API / PDF 共用一套；可单测、可复算。
历史价格快照 JSON价格波动后仍能解释历史报价，不依赖“当时碰巧”的参数。
数据库SQLite 起步单厂 <10 并发足够；切 PostgreSQL 只改配置。
权限Django Groups销售 / 技术 / 财务 / 经理，复用后台与登录体系。

部署与安全

  • 同域挂载：Nginx 增加 /quote/ location，现有标准库页面零改动。
  • 价格隔离：材料价、成本明细仅登录可见；销售默认只看报价，不看成本底牌。
  • 后台保护：/admin/ 限制内网 / VPN，强密码 + 失败锁定。
  • 备份：每日 db.sqlite3 + 报价 PDF 归档；恢复演练纳入上线清单。
  • 审计：报价版本、审批意见、价格变更全部留痕；关键表禁止物理删除。
当前服务器：1 核 1G 起步，Gunicorn 3 worker 约 300 MB；报价模块无额外常驻进程。

把报价做成一条有规则的流水线

版本化

报价模型

成本可解释，价格可复算

每一个数字都来自标准库、价格库或明确的手工输入；没有隐藏系数，也没有“上次就是这么报的”。

COST & PRICE FORMULA · 单件口径
毛坯重=净重÷材料利用率
材料费=毛坯重×材料单价(元/kg)
加工费=规格档基价×类型系数×工艺系数
单件成本=材料费 + 加工费 + 表面处理 + 检测 + 包装 + 运费 + 管理费
含税单价=单件成本×(1+利润率)×(1−客户折扣)×(1−数量优惠)×(1+税率)
毛利率=(不含税金额 − 成本合计)÷不含税金额
舍入：重量 2 位小数（内部计算保留 3 位）、单价与金额 2 位小数；先算单件、再乘数量，最后计税。外币报价按报价日汇率折算，并在报价单注明汇率基准。

成本项拆解

演示默认值仅用于验证模型；正式使用前由财务按实际采购与工时替换。

成本项计算口径数据来源演示默认值
材料费毛坯重 × 材料单价（元/kg）标准库重量 / 几何估算 + 材料价格库A105 7.2 元/kg

定价口径

三种模式
模式适用规则
成本加成标准件 / 新客户成本 × (1+利润率)，折扣与毛利红线校验
客户协议价年框 / 大客户价格表优先；低于协议底价必须审批
市场跟价竞品 / 项目投标手工单价，系统反算毛利并提示红线
  • 价格优先级：协议价 > 价格表 > 成本加成；手工价永远触发复核。
  • 底价保护：低于“材料 + 加工”可变成本直接阻断，不进入审批。
  • 有效期：默认 15 天；原材料波动超过 3% 时提示重算。

SKU 定义

1,348
SKU=标准×类型×压力等级×公称尺寸
报价明细=SKU+材质+工艺选项+数量
  • SKU 是唯一键：标准 + 类型 + 等级 + 口径，对应一条 DimensionRow。
  • 材质是变体：23 个材质主数据，价格与密度独立维护，不复制 1,348 条规格。
  • 工艺是选项：表面处理、检测、包装、运费不进入 SKU，作为报价行参数。
  • 标准版本进快照：报价单记录引用的是 B16.5-2025 还是上一版。

为什么不能直接拿“规格”当“商品”

数据边界
  • 同一 SKU 可对应 9 种材质，价格相差 5–8 倍，必须按材质变体报价。
  • 标准只给尺寸与近似重量，不给毛坯、工时、表面处理与运费。
  • EN / JIS 的滑套、JIS 对焊等规格没有标准重量，需要估算模型兜底。
  • 压力等级不是固定压力，必须按材料组与设计温度查表校验。
  • 标准版本会更新，报价与合同必须能追溯到具体版本。
结论：标准库是“只读主数据”，报价系统在其上增加 材质、价格、工艺、单据 四层业务数据，而不是把报价字段塞进标准表。

重量引擎

四个来源、五类公式、三道校验

报价里的“重量”其实有三个口径：净重、毛坯重、运输重。先分清用哪个，再用可信度分级 + 实测闭环保证准确性； 不能把参考重量当成精密称重，也不能用一个 7.85 算遍所有材质。

C/f：标准已定义，数据已归一

标准里 C 和 f 都有明确定义，不需要报价时让你选。本数据包导入时已统一为“本体厚度 th + 密封面高度 f”，制图和重量引擎都按 th + f 处理。

  • 标准库口径：th 是本体厚度（不含 f），总厚 = th + f。4″：22.4 + 1.5 = 23.9。
  • 只有旧 Excel：如果客户表里的“厚度”是总厚（已含 f），导入时做一次列映射/减 f，不改计算公式。
  • 为什么留开关：--c-includes-f 只用于旧表核对，不是业务选项。

三道校验

自动执行
  • 标准 ↔ 几何互检：两者差异 >10% 标记复核，优先标准值；无标准值则标 C 级。
  • 几何合法性：内径 < 外径、轮毂 ≤ 外径、长度 > 厚度、重量在合理范围；异常值直接阻断。
  • 实测校准：按类型 / 口径分箱，季度用实际过磅回算中位与 90 分位；超标就重新拟合系数。

当前模型：整体中位 5.1%，盲板 3.2%，对焊 8.5%，滑套 5.8%；小口径个例可达 ±40%，所以 C 级必须可复核。

三个重量口径，不要混用

常见错误
口径算法用在哪
净重参考重量 / 几何报价单展示、元/kg 换算
毛坯重净重 ÷ 材料利用率材料费 = 毛坯重 × 单价
运输重净重 + 包装 / 托盘运费、装箱单

把“净重”直接乘材料单价，会漏掉加工余量和下料损耗；把“毛坯重”当运输重，会多算运费。三个口径分开存、分开用，报价单只展示净重。

准确性的边界：参考重量本身是近似值，几何是估算，任何系统都不能承诺“所有规格 100% 准”。可交付的保证是：每一条重量都有来源、置信度和误差带；C/D 级自动进入复核；关键订单用实际过磅 / 图纸结算。系统把不确定性摆到台面上，而不是藏在一个数字里。
