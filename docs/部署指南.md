# 法兰标准库 · 部署指南

本文回答「部署到服务器上有什么要求」，并给出从零到上线的完整步骤。
本地开发运行见 [README](../README.md)；设计方案见 [设计方案](设计方案.md)。

> 结论：**一台 1 核 1G 的 Ubuntu 22.04/24.04 轻量服务器就够**。如果已经有跑
> ax-forge.com 的那台阿里云香港轻量（2 核 2G），直接复用即可，不需要再买服务器、
> 也不需要 ICP 备案。
>
> **本次实际部署**（2026-11-05 更新）：复用现有服务器，正式域名 `https://std.ax-forge.com/`（旧 `/std/` 已 301）
> 路径下（原因和完整记录见 [部署记录](部署记录.md)）。如果 Cloudflare 有 DNS 编辑权限，
> 改成 `std.ax-forge.com` 子域名会更干净，步骤见部署记录第 7 节。

## 1. 服务器要求

### 1.1 最低配置（只跑标准库）

| 项目 | 要求 | 说明 |
|---|---|---|
| CPU / 内存 | 1 vCPU / 1 GB | Django + Gunicorn 3 worker 常驻约 250–400 MB |
| 磁盘 | 20 GB SSD | 代码 + 数据包约 60 MB，SQLite < 10 MB；Chromium/PDF 约 700 MB |
| 带宽 | 1–3 Mbps | 页面以文本和 SVG 为主，没有大图 |
| 系统 | Ubuntu 22.04 / 24.04 LTS | Debian 12 也可以；不推荐 CentOS 7（Python 太旧） |
| Python | 3.10 – 3.12 | Ubuntu 22.04 自带 3.10，24.04 自带 3.12 |
| 端口 | 22 / 80 / 443 | 80/443 对公网，Gunicorn 只听 127.0.0.1:8011 |
| 数据库 | SQLite（默认） | 后台录入是低频写入，1,348 行数据 SQLite 足够；要多人并发再切 PostgreSQL |
| PDF 生成 | Playwright + Chromium | 手机不支持 `window.print()` 时提供「下载 PDF」；需要约 700 MB 磁盘 |

### 1.2 推荐配置（和现有站点共用）

| 项目 | 建议 |
|---|---|
| 产品 | 阿里云**轻量应用服务器**，地域**中国香港** |
| 配置 | 2 核 2G / 40–60G SSD / 3–5 Mbps（现有 ax-forge 那台即可） |
| 镜像 | Ubuntu 22.04 / 24.04 LTS |
| 域名 | 已有域名加一条 A 记录：`std.ax-forge.com` → 服务器 IP |
| HTTPS | Let's Encrypt（certbot）或 Cloudflare Full (strict) |
| 备案 | 香港服务器**不需要 ICP 备案**；如果放中国大陆服务器，域名必须先备案 |

### 1.3 需要准备的账号/权限

- 服务器 root（或 sudo）权限，用于首次安装；
- 一个普通发布用户 `deploy`（`setup-server.sh` 会自动创建，并继承 root 的 SSH 公钥）；
- 域名 DNS 管理权限；
- 如果要限制后台访问：公司出口 IP 或 VPN 网段。

### 1.4 部署后的资源占用（实测估算）

| 进程 | 内存 |
|---|---|
| Nginx | 10–20 MB |
| Gunicorn（3 worker） | 250–350 MB |
| SQLite + 系统 | 剩余 |
| 代码 + 数据包 + 静态文件 | < 80 MB 磁盘 |

1G 内存机器建议 `GUNICORN_WORKERS=2`；2G 用 3 个 worker。

## 2. 两种部署路线

### 路线 A：复用现有阿里云香港服务器（推荐，零新增成本）

现有 ax-forge.com 是 Nginx 静态站，再挂一个 Django 站点完全没问题：

- 新开 Nginx `server_name std.ax-forge.com`，反向代理到 `127.0.0.1:8011`；
- 现有站点配置不动；
- 证书单独给子域名签一张；
- 内存 2G 同时跑静态站 + Django + 询盘服务足够。

### 路线 B：新买一台轻量服务器

- 1 核 1G 即可起步，约每月几十元；
- 适合想和现有站点隔离、单独备份/重启的场景；
- 系统选 Ubuntu 22.04/24.04，地域按访问人群选（香港免备案，面向国内可考虑大陆 + 备案）。

## 3. 从零到上线（路线 A/B 通用）

以下命令都在你自己的 Mac 上执行，服务器地址用 `SERVER_IP` 代替。

### 3.1 准备服务器

1. 阿里云控制台 → 防火墙：放行 **22 / 80 / 443**；
2. 域名加 A 记录：`std.ax-forge.com` → 服务器 IP（Cloudflare 可开橙色云）；
3. 确认能 SSH 登录：`ssh root@SERVER_IP`。

### 3.2 第一次上传代码 + 初始化

```bash
cd "/Users/manshu/网站/标准库"

# 1) 建目录并上传代码（root 上传，setup 脚本会 chown 给 deploy）
ssh root@SERVER_IP 'mkdir -p /srv/flange-std/app'
rsync -az --delete \
  --exclude '.venv/' --exclude '__pycache__/' --exclude '*.pyc' \
  --exclude 'db.sqlite3' --exclude 'staticfiles/' --exclude '.git/' \
  --exclude '.DS_Store' --exclude 'docs/images/' \
  ./ root@SERVER_IP:/srv/flange-std/app/

# 2) 服务器初始化（装依赖、建用户、写 env、装 systemd/Nginx）
ssh root@SERVER_IP 'bash /srv/flange-std/app/deploy/setup-server.sh std.ax-forge.com'
```

脚本会：

- 安装 `python3-venv`、`nginx`、`rsync`、`certbot`；
- 创建 `deploy` 用户，建 `/srv/flange-std/{app,venv}`、`/var/lib/flange-std`；
- 生成 `/etc/flange-std/env`（随机 SECRET_KEY、域名、HTTPS、SQLite 路径）；
- 安装 `flange-std.service` 和 Nginx 站点配置并 reload。

### 3.3 首次发布（含数据导入）

```bash
# 先确认 deploy 用户能 ssh（setup 已复制 root 公钥）
ssh deploy@SERVER_IP 'echo ok'

# 首次发布：装依赖、迁移、收集静态文件、导入 1,348 条数据、启动服务
./deploy/deploy.sh deploy@SERVER_IP --import
```

健康检查应返回：

```json
{"status": "ok", "database": "ok"}
```

### 3.4 申请 HTTPS

```bash
ssh root@SERVER_IP 'certbot --nginx -d std.ax-forge.com'
```

Certbot 会自动修改 Nginx 配置、加 443 和续期任务。然后：

```bash
# 把 env 里的 SITE_URL / CSRF 域名改成 https（setup 已经写成 https，这一步通常不用改）
ssh root@SERVER_IP 'grep SITE_URL /etc/flange-std/env'
ssh root@SERVER_IP 'systemctl restart flange-std'
```

访问 `https://std.ax-forge.com/`，确认首页、规格卡、打印页都正常。

### 3.5 建后台账号

```bash
ssh deploy@SERVER_IP 'cd /srv/flange-std/app && set -a && . /etc/flange-std/env && set +a && /srv/flange-std/venv/bin/python manage.py createsuperuser'
```

### 3.6 日常更新

```bash
cd "/Users/manshu/网站/标准库"
./deploy/deploy.sh deploy@SERVER_IP
```

改了 `flange-standards-data/` 里的数据后：

```bash
./deploy/deploy.sh deploy@SERVER_IP --import
```

发布脚本会：rsync 代码 → `pip install -r requirements.txt` → `migrate` → `collectstatic` →（可选）`import_standards` → `systemctl restart flange-std` → 调 `/healthz`。

## 4. 关键配置说明

### 4.1 环境变量（`/etc/flange-std/env`，权限 600）

| 变量 | 值 | 作用 |
|---|---|---|
| `DJANGO_DEBUG` | `0` | 生产必须关；关掉后模板错误不再暴露堆栈 |
| `DJANGO_SECRET_KEY` | 随机 64 位 | setup 用 `openssl rand -hex 32` 生成 |
| `DJANGO_ALLOWED_HOSTS` | `127.0.0.1,localhost,std.ax-forge.com` | 允许的 Host |
| `DJANGO_CSRF_TRUSTED_ORIGINS` | `https://std.ax-forge.com` | 后台登录 CSRF |
| `DJANGO_HTTPS` | `1` | 启用 Secure Cookie、HSTS、代理 HTTPS 识别 |
| `SITE_URL` | `https://std.ax-forge.com` | 打印页页脚的完整地址 |
| `DJANGO_SCRIPT_NAME` | 空，或 `/std` | 挂在主域名子路径时设置；独立子域名留空 |
| `PLAYWRIGHT_BROWSERS_PATH` | `/var/lib/flange-std/ms-playwright` | Chromium 路径 |
| `PDF_RENDER_BASE_URL` | `https://127.0.0.1/std` 或 `https://std.example.com` | PDF 渲染的内部打印页地址 |
| `PDF_CACHE_DIR` | `/var/lib/flange-std/pdf` | PDF 缓存目录 |
| `DJANGO_DB_PATH` | `/var/lib/flange-std/db.sqlite3` | 数据库放代码目录外，发布不覆盖 |
| `GUNICORN_WORKERS` | `2` 或 `3` | 1G 用 2，2G 用 3 |

改完执行 `systemctl restart flange-std`。

### 4.1.1 PDF 生成（Playwright）

手机（尤其 iPhone Safari）的 `window.print()` 不会弹出打印对话框，因此站点提供
`/spec/<id>/pdf/` 服务端生成 PDF。依赖：

```bash
# 在服务器上，用 deploy 用户安装 Python 包
sudo -u deploy /srv/flange-std/venv/bin/pip install playwright
# 安装 Chromium 和系统依赖（约 700 MB 磁盘）
sudo -u deploy env PLAYWRIGHT_BROWSERS_PATH=/var/lib/flange-std/ms-playwright \
  /srv/flange-std/venv/bin/playwright install chromium
/srv/flange-std/venv/bin/playwright install-deps chromium
```

`/etc/flange-std/env` 需要：

```ini
PLAYWRIGHT_BROWSERS_PATH=/var/lib/flange-std/ms-playwright
PDF_CACHE_DIR=/var/lib/flange-std/pdf
PDF_RENDER_BASE_URL=https://127.0.0.1/std   # 路径挂载；子域名改成 https://std.example.com
PDF_LAYOUT_VERSION=1                        # 改了打印样式后 +1，强制重新生成
```

生成的 PDF 缓存在 `/var/lib/flange-std/pdf/`；`row.updated_at` 变化会自动重新生成。
如果服务重启后 PDF 报 503，先看 `journalctl -u flange-std -n 50` 里 Playwright/Chromium 的报错。

### 4.2 静态文件

`collectstatic` 输出到 `/srv/flange-std/app/staticfiles/`，Nginx 直接发 `/static/`，不经过 Django。
静态资源在 Nginx 侧缓存 7 天，模板里的 CSS 链接带了 `?v=YYYYMMDDx`；**改 CSS/JS 后把这个版本号 +1**，
否则浏览器/Cloudflare 可能继续用旧文件。然后重新发布。

### 4.3 进程管理

```bash
systemctl status flange-std
journalctl -u flange-std -f          # 应用日志
journalctl -u flange-std -n 200      # 最近 200 行
```

Gunicorn 访问日志和错误日志都进 journald，Nginx 日志在 `/var/log/nginx/`。

### 4.4 健康检查

```bash
curl -s https://std.ax-forge.com/healthz
# {"status": "ok", "database": "ok"}
```

数据库不可用时返回 503，可接阿里云云监控 / UptimeRobot。

### 4.5 数据库

默认 SQLite，文件在 `/var/lib/flange-std/db.sqlite3`。

想切 PostgreSQL（多人同时录入、或要做主从/自动备份）：

```bash
sudo apt install -y postgresql
sudo -u postgres createuser flange -P
sudo -u postgres createdb -O flange flange_std
```

在 `/etc/flange-std/env` 里启用：

```ini
DJANGO_DB_ENGINE=django.db.backends.postgresql
DJANGO_DB_NAME=flange_std
DJANGO_DB_USER=flange
DJANGO_DB_PASSWORD=...
DJANGO_DB_HOST=127.0.0.1
DJANGO_DB_PORT=5432
```

然后 `pip install "psycopg[binary]"`、`migrate`、`import_standards`、重启。
（`psycopg` 需要加进 `requirements.txt`，或用 `pip install` 单独装。）

## 5. 备份与恢复

### 5.1 每天备份（cron）

```bash
sudo mkdir -p /var/lib/flange-std/backups
sudo crontab -e
```

加一行（每天 3:10，保留 14 天）：

```cron
10 3 * * * /usr/bin/sqlite3 /var/lib/flange-std/db.sqlite3 ".backup '/var/lib/flange-std/backups/db-$(date +\%F).sqlite3'" && find /var/lib/flange-std/backups -name 'db-*.sqlite3' -mtime +14 -delete
```

代码和数据包本身由 `deploy.sh` 从本机发布，服务器上不需要单独备份源码。
更稳妥：每天把 `db-*.sqlite3` 同步到本机或对象存储（`rclone` / `scp`）。

### 5.2 恢复

```bash
sudo systemctl stop flange-std
sudo cp /var/lib/flange-std/backups/db-2026-11-04.sqlite3 /var/lib/flange-std/db.sqlite3
sudo chown deploy:deploy /var/lib/flange-std/db.sqlite3
sudo systemctl start flange-std
```

## 6. 安全清单

- [ ] `DJANGO_DEBUG=0`
- [ ] `DJANGO_SECRET_KEY` 是随机值，不是仓库里的默认值
- [ ] `ALLOWED_HOSTS` 只写正式域名 + 本机
- [ ] `/admin/` 用 Nginx 限制到公司 IP / VPN（见 `deploy/nginx-flange-std.conf` 注释块）；
      不限制也可以，但至少改掉演示密码
- [ ] 后台账号用强密码，不用 `admin/admin12345`
- [ ] 只开放 22/80/443；SSH 用密钥登录，建议关掉密码登录
- [ ] 证书自动续期：`systemctl status certbot.timer`
- [ ] 每天备份数据库，并定期演练恢复
- [ ] Cloudflare 代理时 SSL 模式选 Full (strict)

## 7. 常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 502 Bad Gateway | `systemctl status flange-std`，看是否启动失败；`journalctl -u flange-std -n 100` |
| 400 Bad Request | `ALLOWED_HOSTS` 没加当前域名；改 env 后重启 |
| 静态文件 404 | 没跑 `collectstatic`，或 Nginx alias 路径不对；重新发布 |
| 后台 CSRF 403 | `DJANGO_CSRF_TRUSTED_ORIGINS` 没写 `https://域名` |
| 打印页 URL 是 127.0.0.1 | `SITE_URL` 没改成正式域名 |
| 中文在 PDF 里空白 | 打印样式字体栈被改了；保留 `Arial Unicode MS` 优先（见设计方案 7.3） |
| 证书续期失败 | 80 端口被安全组/防火墙挡住；certbot 需要 80 验证 |
| 内存不够 / 服务被 OOM | 1G 机器把 `GUNICORN_WORKERS` 调成 2 |

### 5.3 回滚（发布失败时）

代码回滚和数据库回滚分开做；**先备份，再回滚**。

1. **发布前快照**：`deploy.sh` 在 rsync 前会把当前代码打到
   `/srv/flange-std/releases/app-<时间>.tar.gz`；保留最近 3–5 份。
2. **停服务**：`sudo systemctl stop flange-std`
3. **恢复数据库**（先确认备份文件）：
   ```bash
   sudo cp /var/lib/flange-std/backups/db-<发布前>.sqlite3 /var/lib/flange-std/db.sqlite3
   sudo chown deploy:deploy /var/lib/flange-std/db.sqlite3
   ```
4. **恢复代码**：
   ```bash
   sudo tar -xzf /srv/flange-std/releases/app-<发布前>.tar.gz -C /srv/flange-std
   ```
5. **恢复依赖/静态**：`$VENV/bin/pip install -r requirements.txt`、`collectstatic`
6. **启动并验证**：`systemctl start flange-std`，检查 `/healthz`、`/quote/`、一张报价单详情/打印。
7. **记录**：回滚原因、版本、数据库备份文件、验证人，写入发布记录。

> 迁移已经执行过的字段，代码回滚后不要盲目 `migrate --fake`；优先用数据库备份恢复，
> 或按迁移文件逐个反向迁移并在 staging 验证。

### 5.4 报价功能上线门（必须全过）

```bash
python manage.py check
python manage.py test quote
python manage.py seed_roles
python manage.py check_prices          # 必须 real / 无 demo；详见 docs/报价上线-待提供数据清单.md
python manage.py migrate --noinput
```

- 价格库仍有 `source=demo`：**禁止开放正式报价**（可先做 staging/UAT）。
- PDF：staging 安装 Playwright/Chromium，或设置 `PDF_CHROME_BIN` 指向 Chrome/Chromium；
  实际下载一张 A4 单页报价单。
- 并发：SQLite 已启用 WAL + 写锁重试，小团队可用；多人同时录单建议 PostgreSQL。
- UAT：20 张历史报价回放，销售/财务/经理签字。
- `/etc/flange-std/env` 设置 `REQUIRE_REAL_PRICES=1`，`deploy.sh` 会在迁移后执行 `check_prices`，有 demo/缺失价直接中止发布。
